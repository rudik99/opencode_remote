# Claude Code Subscription Bridge

This stack can delegate bounded tasks from OpenCode to the official, unmodified Claude Code CLI. The delegated process authenticates with your own Claude Pro, Max, Team, or Enterprise subscription.

This is not an Anthropic provider for OpenCode. OpenCode still needs its own main model provider to orchestrate the session. The bridge calls Claude Code as a guarded tool, and the selected Claude model handles only the delegated task.

## Security Model

- The image installs the official `@anthropic-ai/claude-code` package at `CLAUDE_CODE_VERSION`.
- Authentication uses the one-year token generated by the official `claude setup-token` flow.
- The token is stored only in the ignored stack `.env` file and passed through `CLAUDE_CODE_OAUTH_TOKEN`.
- The bridge removes API-key and cloud-provider credentials from the Claude child process so the subscription token wins Claude Code's authentication precedence.
- OpenCode asks for permission before every `claude_code` invocation.
- Analyze mode is read-only. Edit mode permits Claude Code file reads and edits, but not shell, web, browser, or MCP tools.
- Safe and restricted modes ignore project hooks, plugins, and settings while confining file tools to the working directory.
- Delegated sessions use `--no-session-persistence`, have a bounded turn count, and time out after 30 minutes.
- OpenCode remains responsible for running tests, builds, and other verification after Claude edits files.

Do not use third-party OAuth plugins that collect Claude credentials or rewrite OpenCode requests to impersonate Claude Code. Anthropic explicitly prohibits routing Pro or Max credentials through third-party applications. This bridge runs Anthropic's published Claude Code binary with the user's own authentication.

`CLAUDE_CODE_VERSION` defaults to `latest`, resolved when the image is built. Rebuild the image to receive a newer release, or set an explicit version in `.env` when reproducible builds are required.

## Initial Authentication

Build and start the stack before generating the token:

```bash
docker compose up -d --build
```

Start the official token flow from a terminal attached to the host:

```bash
docker compose exec opencode claude setup-token
```

Open the authorization URL, authenticate directly with Anthropic, and complete the prompt. Claude Code prints the token once and does not save it.

Open the ignored stack environment file without putting the token in shell history:

```bash
nano .env
```

Add:

```dotenv
CLAUDE_CODE_OAUTH_TOKEN=your-generated-token
```

Secure the file and recreate only OpenCode so Compose injects the new value:

```bash
chmod 600 .env
docker compose up -d --no-deps --force-recreate opencode
```

Verify authentication without displaying the token:

```bash
docker compose exec opencode claude auth status --text
```

Never paste the token into chat, a command argument, source control, an issue, or a pull request.

## Usage

Use the `/claude` command followed by an optional model alias and a task:

```text
/claude opus review the authentication architecture and report risks
/claude sonnet update the parser and add focused tests
/claude haiku summarize this module
/claude explain the current data flow
```

Available aliases are `default`, `sonnet`, `opus`, and `haiku`. The `default` alias lets Claude Code choose the subscription's configured default. Actual model availability and usage limits depend on the authenticated subscription.

You can also request delegation naturally:

```text
Ask Claude Code with opus to review this design without changing files.
Use Claude Code sonnet to implement this change.
```

The OpenCode orchestrator chooses `analyze` for read-only work and `edit` only when modification is explicitly requested. OpenCode displays a permission prompt before launching Claude Code.

## Existing Installations

Bootstrap does not overwrite an existing `data/config`. After updating an established stack, merge these versioned files into the live configuration:

```text
config-template/tools/claude_code.ts   -> data/config/tools/claude_code.ts
config-template/command/claude.md      -> data/config/command/claude.md
```

Also merge the `permission.claude_code` rule from `config-template/opencode.jsonc`, then rebuild and recreate OpenCode:

```bash
docker compose build opencode
docker compose up -d --no-deps --force-recreate opencode
```

## Renewal And Revocation

Claude Code warns before a subscription token expires. Generate a replacement with `claude setup-token`, replace only the value in `.env`, and recreate OpenCode.

If the token may have been exposed, revoke the affected Claude session in your Anthropic account, generate a replacement, and recreate the service. Deleting the token from a file does not revoke a copied credential.

## Troubleshooting

### Claude Code reports that it is not logged in

Confirm the variable is present in `.env`, recreate the service, and rerun:

```bash
docker compose exec opencode claude auth status --text
```

A plain `docker compose restart opencode` does not apply changed Compose environment values; recreate the service.

### The `/claude` command or `claude_code` tool is missing

Confirm the command and tool files exist under `data/config`, merge the permission rule, and recreate OpenCode. Config-time files are loaded only at startup.

### A requested model is unavailable

Use `default` or another alias included in your subscription. Subscription entitlements and model availability can change independently of this stack.

### Claude edited files but did not run tests

This is intentional. The bridge denies Claude Code shell access. OpenCode should inspect the diff and run the repository's tests and build using its own permission-controlled tools.

### OpenCode restarted during a delegation

The Claude Code child process stops with the OpenCode container. Reopen the persisted OpenCode session, inspect the workspace for partial edits, and delegate the remaining work again if needed. The bridge does not persist or automatically replay delegated sessions because replaying a partially completed edit can duplicate or overwrite work.
